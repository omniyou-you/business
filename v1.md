# Self-Service Printing Kiosk — Finalized Core System Flow (V1)

## System Overview
Current Scope: Web upload → Print options selection → Simulated (fake) payment → Print Code / QR code generation → Saved print job record → (Future) Mini-PC verification and printing.

*Note: Cash acceptance hardware and live production payment gateway integration are excluded from V1 scope.*

---

## 1. Current Web System Flow
The first development phase is a web application where the user uploads a PDF, selects printing options, views the calculated price, completes a simulated test payment, and receives a Print Code and QR code.

```
USER
  │
  ▼
WEBPAGE
  │
  ├─► Upload PDF
  ├─► Select printing options
  ├─► Calculate price
  ├─► FAKE PAYMENT (Simulated)
  ├─► Payment = VERIFIED
  ├─► Generate Print Code & QR
  ├─► Save EVERYTHING to Database
  └─► Show Code + QR to User
```

---

## 2. Future Mini-PC / Kiosk Flow
The Mini-PC kiosk will accept the user's Print Code / QR, request authorization from the backend, and only print after backend confirmation.

```
MINI PC / KIOSK
  │
  ├─► User enters or scans Print Code
  │
  ├─► Mini PC ──(POST /verify-print-code)──► Backend
  │                                             │
  │   Backend Verification Checks:              │
  │   [✔] Code exists in database?              │
  │   [✔] Payment verified?                     │
  │   [✔] Code not expired?                     │
  │   [✔] Order not already printed?            │
  │   [✔] Machine ID authorized?                │
  │   [✔] File available in storage?            │
  │                                             │
  ├─◄ Backend returns complete print-job details ◄┘
  │
  ├─► Mini PC downloads PDF file
  ├─► Mini PC sends PDF to local printer
  ├─► Printing completes
  └─► Mini PC ──(POST /mark-printed)──► Backend updates status to PRINTED/COMPLETED
```

---

## 3. Order ID & Print Code Strategy
Each print operation utilizes two separate identifiers:
* **Order ID**: Internal unique primary key/identifier (e.g., `ORD-2026-000001`).
* **Print Code**: Short numeric or alphanumeric code used by the user at the kiosk for verification (e.g., `583921`).

---

## 4. Complete Data Model (Print Job Schema)

| Field | Type / Description | Purpose |
| :--- | :--- | :--- |
| `order_id` | String / UUID | Unique order identifier (e.g., `ORD-2026-000001`) |
| `print_code` | String (Index) | Short code used for kiosk verification (e.g., `583921`) |
| `pdf_file_id` | String | Reference ID to uploaded PDF asset |
| `file_name` | String | Original PDF filename |
| `file_storage_location` | String / Path | Internal object storage reference / file path |
| `page_count` | Integer | Total calculated pages in PDF |
| `copies` | Integer | Number of copies requested |
| `paper_size` | Enum | Paper size (`A4`, `A3`, `Letter`, `Legal`) |
| `color_or_black_white` | Boolean / Enum | Color (`color`) vs B&W (`bw`) |
| `single_or_double_sided` | Enum | Simplex (`single`) vs Duplex (`double`) |
| `orientation` | Enum | `portrait` vs `landscape` |
| `scaling` | String / Enum | `fit_to_page`, `actual_size`, custom scaling |
| `selected_printer_options` | JSON / Object | Additional custom options |
| `calculated_price` | Decimal / Float | Final calculated price |
| `payment_status` | Enum | `PENDING`, `VERIFIED`, `FAILED` |
| `payment_method` | String | e.g., `TEST_SIMULATED` |
| `payment_transaction_id` | String | Mock or gateway transaction reference |
| `print_status` | Enum | `PENDING`, `AUTHORIZED`, `PRINTING`, `COMPLETED`, `DENIED`, `EXPIRED` |
| `created_at` | Timestamp | Creation timestamp |
| `paid_at` | Timestamp | Payment verification timestamp |
| `expires_at` | Timestamp | Print code expiry timestamp |
| `machine_id` | String (Nullable) | Associated kiosk ID when claimed/printed |
| `printed_at` | Timestamp (Nullable) | Timestamp when printing completed |

## 5. Backend Authorization API

### Request
`POST /verify-print-code`
```json
{
  "code": "583921",
  "machine_id": "KIOSK-001"
}
```

### Authorized Job Response Structure
```json
{
  "authorized": true,
  "order_id": "ORD-2026-000001",
  "file": {
    "download_url": "https://api.kiosk.local/storage/pdfs/ORD-2026-000001.pdf",
    "filename": "assignment.pdf"
  },
  "print_settings": {
    "copies": 2,
    "paper_size": "A4",
    "color": false,
    "duplex": true,
    "orientation": "portrait",
    "scaling": "fit_to_page"
  },
  "expires_at": "2026-08-27T20:27:00Z"
}
```

## 6. Double-Print Protection Lifecycle

```
[ FIRST REQUEST ]
  PAID ──► AUTHORIZED ──► PRINTING ──► PRINTED/COMPLETED

[ SECOND / SUBSEQUENT REQUEST ]
  ALREADY_PRINTED ──► DENIED (Access Blocked)
```
